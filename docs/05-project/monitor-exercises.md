# 05-4 · 上位机实战：逐步从能跑到能用

完成 [05-3 WPF 工业监控台](/05-project/wpf-lab) 后，真正重要的是处理**出错时程序会怎样**。本节作为你的验收与练习册。

## 实验 1：断开和重连

先启动 `python examples/05-modbus-tcp-simulator/simulator.py --dynamic`，打开 WPF 监控台并连接。

接着停止 Python 进程，观察窗口上的连接状态是否变为“连接或采集异常”。确保温度保持为最后一次值，**不要将其误认为实时值**。

再重启模拟器，点击连接按钮。你需要观察：只有一条采集循环，并且每次读取有自己的事务 ID。

**验收：** 通信失败可观察，重新连接能恢复，没有 UI 冻结或额外的后台死循环。

## 实验 2：识别“高温报警”

动态模拟器每秒让温度上升 0.6 ℃（在达到峰值后下降）。默认报警阈值是 32.0 ℃。

```text
25.3 ℃ → 25.9 ℃ → … → 32.5 ℃ → 进入高温 → … → 31.9 ℃ → 恢复
```

连续处于高温的每一秒应更新状态，但只有第一次跨过阈值时记录“告警”。当温度降到阈值以下，只写一次“恢复”。

**验收：** 不出现每秒重复弹窗，也不因为一次报警把界面锁死。

## 实验 3：SQLite 数据持久化

在 Windows PowerShell 查询数据库：

```powershell
python -c "import os,sqlite3; p=os.path.join(os.environ['LOCALAPPDATA'],'HostComputerLearn','monitor.sqlite'); con=sqlite3.connect(p); print(con.execute('select count(*),min(temperature_c),max(temperature_c) from readings').fetchone())"
```

注意：这里显示的是已保存数据；如果监控台刚刚收到一帧但后台还没写入，瞬间查询不一定马上可见。正常退出后队列应该清空。

## 实验 4：CSV 导出与 SQL 查询

CSV 文件应包含：时间、温度、压力、转速、报警标志。用 SQLite 查询高温记录：

```sql
SELECT captured_at_utc, temperature_c, rpm
FROM readings
WHERE alarm = 1
ORDER BY id DESC LIMIT 10;
```

**验收：** 你能解释：为什么监控台事件面板只有 30 条，数据库却能保存更多历史。

## 实验 5：改造报警

复制 `MainViewModel.cs` 中的报警状态变化逻辑，新增压力高于 110 kPa 的规则。推荐先把阈值改为 101.3 kPa，使用模拟数据快速测试。

要做到：报警进入只产生一次，恢复只产生一次。此时你已开始练习“业务状态机”。

## 实验 6：生产系统还缺什么？

本项目还不能直接用于工厂。你至少需要考虑：

- 真正设备地址和寄存器表的差异、认证与网络隔离。
- 设备控制命令的安全联锁、权限与确认。
- 多设备周期轮询、网络和设备负载限制。
- 告警历史、确认/解除流程、阈值配置。
- 离线缓存策略、数据清理与索引维护。
- 现场长期运行测试、安装包和故障恢复。

不要一开始就加入所有功能。**先能重现，再理解为什么需要它。**
