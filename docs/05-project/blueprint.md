# 05-1 · 毕业项目：工业设备监控台

你最终要能拿去演示的，不是一个串口按钮集合，而是**可以维护设备连接生命周期、展示实时数据、留下可追溯记录的 Windows 桌面应用**。

## 产品蓝图

```text
┌───────────────────────────────────────────────────┐
│  设备监控台           设备在线 2 / 3    最后采集时间    │
├────────────┬──────────────────────────────────────┤
│ 设备导航    │ 温度         压力          转速          │
│            │ 23.5 ℃      101.2 kPa      1200 rpm      │
│ ● 一号设备 │──────────────────────────────────────│
│ ● 二号设备 │ 历史趋势 / 最近告警                       │
│ ○ 三号设备 │                                     │
├────────────┴──────────────────────────────────────┤
│ 事件日志：连接成功 | 接收异常 | 参数设置 | 设备离线    │
└───────────────────────────────────────────────────┘
```

## 最小架构

```text
MainWindow (WPF XAML)
  ↕ Binding / ICommand
MainViewModel
  ↓
DeviceSession（连接、接收、取消、重连策略）
  ↓
Transport（TcpClient / SerialPort）
  ↓
ProtocolParser（协议解析、校验）
  ↓
DeviceSnapshot（温度/压力/转速/状态）
  ├─> UI （频率限流，避免每报文重新绘制）
  └─> Storage （后台批量写入 SQLite/CSV）
```

v0.1 的 WPF 示例只实现一个设备的**连接 + 实时数值**，以保持初学者理解成本低。设计中的设备管理、告警、历史数据和存储属于后续版本，尚未声称实现。

## 数据与交互要求

- 设备未连接时显示离线，不得显示误导性的实时状态。
- 高风险控制（启动电机、开阀）必须二次确认、权限校验及回读验证；本书演示不直接控制真机。
- 所有设备帧的原始数据、解析结果和错误信息应能追踪。
- “断网 → 提示离线 → 手动或受控重连”是必须演练的路径。

## 推荐迭代顺序

1. 完整运行本书 TCP 模拟器与 WPF 监控界面。
2. 添加设备会话状态机和自定义连接地址。
3. 替换模拟文本协议为 Modbus TCP，增加寄存器地图。
4. 添加最近 100 条采样列表和告警提示。
5. 写入 SQLite 并提供查询与 CSV 导出。
6. 形成一份真实可验证的部署与联调验收报告。

**验收：** 能完整讲解从网络 I/O 到 ViewModel、UI 的数据流向，并演示至少一个断线恢复场景。
