# 04-1 · Modbus RTU / TCP 入门

Modbus 是工业设备间常见的请求/响应协议。**Modbus TCP 运行在 TCP 上；Modbus RTU 常运行在串口线路上。** 两者都经常用功能码描述读取/写入哪一类数据，但传输帧封装不同。

## 四种逻辑数据区

| 数据区 | 典型能力 | 常见功能码 |
| --- | --- | --- |
| Coil（线圈） | 可读写的单个位 | 01 读，05/0F 写 |
| Discrete Input（离散输入） | 只读位 | 02 读 |
| Input Register（输入寄存器） | 只读 16 位寄存器 | 04 读 |
| Holding Register（保持寄存器） | 可读写的 16 位寄存器 | 03 读，06/10 写 |

这些是 Modbus 协议的数据模型，**具体字段含义、缩放比例与允许操作由设备厂商定义**。

## 两种帧的差异

- **RTU**：地址 + 功能码 + 数据 + CRC16；串口传输的帧间隔与校验很重要。
- **TCP**：MBAP 头 + PDU；头中含事务标识和长度字段，**Modbus TCP 标准报文不附加 RTU CRC**。

常见误区：拿 RTU 请求直接通过 TCP 套接字发给 Modbus TCP 设备，不一定会得到正确响应，因为报文封装并不一样。

## Modbus TCP 报文示意

读取一个保持寄存器：

```text
00 01  00 00  00 06  01  03  00 00  00 01
└TID┘  └PID┘  └长度┘ UID  FC └地址┘  └数量┘
```

- Transaction ID = `0x0001`
- Protocol ID = `0x0000`
- Length = 6（含 Unit ID 及后面的 PDU，共 6 字节）
- Unit ID = 1
- FC = 03
- 起始偏移 = 0，数量 = 1

在真实环境中还要匹配响应的事务 ID、检查功能码/异常响应及报文长度。这里先讲清楚报文基础，下一步可以直接进入 **[04-3 Modbus TCP 真正实战](/04-modbus/tcp-lab)**：已经提供 Python 模拟设备、C# 读取/写入示例以及真实套接字的异常测试。学习串口校验时再做 [04-4 RTU CRC16](/04-modbus/crc-lab)。这两个练习完成后，用 [04-6 自测 12 题](/04-modbus/quiz) 检查是否真正理解。

## 为什么要慢慢学？

先用本书的文本 TCP 模拟器理解长连接与分帧，再学习 Modbus 这一层**二进制应用协议**，避免连接失败、字节解析失败和寄存器配置错误同时发生时无法定位。

## 练习与验收

解释功能码 `03` 与 `04` 的不同；解释为什么标准 Modbus TCP 报文不携带 RTU CRC；写出一个“读取 2 个保持寄存器”的请求 PDU。

**验收：** 能分清 RTU 和 TCP 的封装，以及四种数据区的读写属性。
