# 05-5 · 两台设备同时采集：会话、独立状态、断线重连

> **目标：** 从 v0.3 的单设备监控台升级为两个同时采集的独立 Modbus TCP 会话。你应该学会设计连接生命周期，而不仅是把设备列表放到 WPF 页面上。
>
> 配套源码：[examples/09-multi-device-monitor](https://github.com/yvanu/host_computer_learn_book/tree/main/examples/09-multi-device-monitor)。

## 一、为什么不能只复制两份界面？

假设有两台仪器。很多入门程序只复制两份 UI，却让它们共享一个 `TcpClient` 和一个 `Status`。结果：

- A 设备断开时，B 的状态也跟着显示“离线”。
- A 接收的字节可能被错误解释为 B 的数据。
- 设备地址和事务号难以一一对应。
- 多线程同时访问同一个 TCP stream，容易把请求、响应搞乱。

真正的解决方式是：**一个设备，一份状态，一条采集循环，一份 TCP 连接；数据存储层共享**。

```text
模拟 PLC A :1502 → DeviceSession(A) → DevicePanel(A) ─┐
                       FC03 / 1 秒                   ├→ Channel → SQLite
模拟 PLC B :1503 → DeviceSession(B) → DevicePanel(B) ─┘
                       FC03 / 1 秒
                       ↓ 选中的设备
                      WPF 中间监控区域
```

## 二、实际运行，不买硬件

在两个 PowerShell 终端执行：

```powershell
# 窗口 1：启动两台独立模拟 PLC
python examples/05-modbus-tcp-simulator/simulator.py --devices 2 --dynamic
```

```powershell
# 窗口 2：启动 WPF 多设备监控台
dotnet run --project examples/09-multi-device-monitor/MultiDeviceMonitor.csproj
```

第一台监听 1502，第二台监听 1503。**都绑定 127.0.0.1**，不会开放到真实局域网。

在左侧选“模拟设备 01”点击连接，再选“模拟设备 02”点击连接。切换选中项时，中间温度/压力/转速和曲线应显示各自独立的数据。第二台初始温度稍高，是为了让你看出选中设备确实影响数据展示。

## 三、后端类比：一个 Task 对应一个设备会话

你熟悉 Flask/异步任务：请求上下文各自隔离；设备通信需要长期会话，更强调**取消和资源清理**。

项目里：

- `DevicePanel`：WPF 可观察状态（温度、压力、在线状态、报警阈值）。
- `DeviceSession`：维护一个网络连接的生命周期和采集任务。
- `ModbusDeviceClient`：负责 FC03、事务 ID 和 MBAP 的协议校验。
- `MainViewModel`：管理选中设备与操作按钮，不写二进制帧解析。

`DeviceSession.Start()` 只允许一个仍在运行的采集任务；不会对相同设备再启动第二条轮询。两个设备各有独立实例，互相不共享连接流。

## 四、掉线后为什么不能无限重连？

读请求可以在约束下重新连接，但无限频繁的重连会造成日志爆炸、耗资源，甚至给 PLC 网关造成压力。

本例限定**最多连续 3 次重试**，使用递增等待：

| 失败计数 | 延迟 | 界面显示 |
| --- | --- | --- |
| 第 1 次 | 1 秒 | 掉线，1 秒后重连（1/3） |
| 第 2 次 | 2 秒 | 掉线，2 秒后重连（2/3） |
| 第 3 次 | 4 秒 | 掉线，4 秒后重连（3/3） |
| 再次失败 | 停止 | 离线 · 重试已耗尽 |

**注意计数的语义：** 当一次读取真正成功，连续失败次数重置；这样短暂网络波动恢复后不会带着历史失败次数。三次失败后需要人工点击连接。协议报文格式错误属于配置/数据问题，**不执行自动重连**，先查看报文。

## 五、取消重连 vs 停止正在读取

一个正确的上位机至少要有两类停止能力：

1. 正在 `Task.Delay` 等待退避：`CancellationToken` 让它立刻退出。
2. 正在 `ReadExactlyAsync` 等设备回复：取消 token 且关闭该 `TcpClient`，避免无限堵在 socket 读取中。

这就是为什么“断开按钮”不能只是把 UI 状态字符串改为 `未连接`。

## 六、你需要亲手做的 5 个实验

1. **两个都正常**：同时连接，连续 15 秒，观察两台温度值不同且各自更新。
2. **先停设备再恢复**：完全停止模拟器，观察两个会话分别进入重试；在重试窗口内恢复模拟器，看是否自动连接成功。
3. **超出重试上限**：保持模拟器关闭，等待三次重试耗尽；观察“离线 · 重试已耗尽”。
4. **停止其中一个会话**：在设备 01 的连接或重试阶段点击“断开”，确认设备 02 独立运行。
5. **模拟错误协议**：与早期 Modbus 练习对照，解释为何不应对持续报错的寄存器地址无限重连。
