# 04-3 · 第一个真正的 Modbus TCP 实验

> **目标：** 不用 PLC、不安装第三方 Python 包，你能启动模拟设备、发送真实 Modbus TCP 帧、读出三个保持寄存器，最后理解 C# 程序为什么必须按长度读取。

本课不是“去买硬件”，而是帮你将熟悉的后端 TCP 编程能力迁移到工业协议。

## 1. 运行环境及数据定义

需要 Python 3.10+。如果想跟着练 C#，另外需要安装 .NET 10 SDK，WPF 并不是本课必要条件。

本课采用**专用的本地 Modbus TCP 模拟服务**，地址固定为 `127.0.0.1:1502`。使用 1502 而不是 502，是为了避免低端口权限与现有设备服务冲突。默认仅支持 Unit ID `1`。

| 读保持寄存器偏移（从 0 开始） | 说明 | 初始整数值 | 业务解码 |
| --- | --- | ---: | ---: |
| 0 | 温度（单位 0.1 ℃） | 253 | 25.3 ℃ |
| 1 | 压力（单位 0.1 kPa） | 1012 | 101.2 kPa |
| 2 | 模拟转速（单位 1 rpm） | 1200 | 1200 rpm |

**重要：** 这里的 40001/40002/40003 只是一种常见的资料显示编号，真正请求里的偏移是 `0/1/2`。不要把 `40001` 直接放进 PDU 地址字段。

## 2. 启动模拟设备

打开 PowerShell，进入仓库根目录：

```powershell
python examples/05-modbus-tcp-simulator/simulator.py
```

预期：

```text
Modbus TCP training simulator: 127.0.0.1:1502, unit=1
Holding registers: offset 0=253 (25.3°C), 1=1012 (101.2kPa), 2=1200 rpm
Supports FC03 read and FC06 write offset 2 only; Ctrl+C to stop.
```

这个终端保持运行，第二个终端发送指令。它完全运行在电脑本地，不连接任何 PLC。

## 3. 先看一条真实的请求报文

下面的 12 字节是**读取偏移 0 起连续 3 个 Holding Register**（FC03）的请求：

```text
00 01 00 00 00 06 01 03 00 00 00 03
│TID│ │PID│ │LEN│ U  FC │偏移│ │数量│
```

- `00 01`：事务标识（Transaction ID），本次请求编号为 1。
- `00 00`：协议标识（Protocol ID），标准 Modbus TCP 应为 0。
- `00 06`：长度 = 6，**从 Unit ID 开始**，包含后面 1 个 Unit 字节 + 5 个 PDU 字节。
- `01`：Unit ID = 1。
- `03`：功能码，读保持寄存器。
- `00 00`：起始偏移为 0。
- `00 03`：连续读 3 个寄存器。

注意 **MBAP 头总长 7 字节**，其中最后 1 字节是 Unit ID；后面的 PDU 长度通过 Length 字段计算。

正常响应应是：

```text
00 01 00 00 00 09 01 03 06 00 FD 03 F4 04 B0
                   │  │  │  │温度││压力││转速│
                   U  FC 字节数
```

返回的 `00 FD=253`，`03 F4=1012`，`04 B0=1200`。三个寄存器一共 **6 个数据字节**，所以 `Byte Count=06`，MBAP 的 `Length=09`（Unit ID 1 + PDU 8）。

可以先不运行任何 C#，自己拿纸计算这三组数字与单位。

## 4. 没装 .NET 也能先完整验证通信

另一终端执行：

```powershell
python examples/05-modbus-tcp-simulator/inspect_client.py
```

这个 Python 客户端会打印原始请求/响应帧以及温度、压力、转速的换算值。它使用标准库 socket，重点是**先明白请求发了什么、收到了什么**，而不是一开始就纠结 C# 语法。

## 5. 运行 C# Modbus TCP 客户端

在第二个终端运行：

```powershell
dotnet run --project examples/06-modbus-tcp-client
```

**预期输出（示意，需你本机验证）：**

```text
> 000100000006010300000003
< 00010000000901030600FD03F404B0
温度: 25.3 °C
压力: 101.2 kPa
转速: 1200 rpm
```

客户端采用 `TcpClient` 建立长连接，使用 `ReadExactlyAsync` 先读 7 字节 MBAP，再按 `Length - 1` 读取 PDU；检查 Transaction ID、Protocol ID、Unit ID、功能码及数据长度。

这与上一课的文本行协议不一样：**二进制 Modbus TCP 不存在“遇到换行就结束”**的规则。

## 6. 在模拟器上演示一次写入

只有在确认连接的是**本地模拟器**后再运行：

```powershell
dotnet run --project examples/06-modbus-tcp-client -- write-rpm 1500
```

预期顺序是：先 FC03 读三项 → FC06 写偏移 2 的转速 1500 → 收到原样回显 → 再 FC03 回读偏移 2，确认值为 1500。

写入请求：

```text
00 02 00 00 00 06 01 06 00 02 05 DC
                      FC │地址││1500│
```

正常情况下 FC06 会在响应里**回显地址和值**。但是回显不等于实体电机已经执行成功。真实设备的启动/停止、设置转速等操作必须另外确认安全许可和实际反馈。

## 7. 学会读异常帧

假设请求偏移 `3`，当前模拟器仅有 0/1/2 三个寄存器：

```text
请求功能码：03
异常功能码：83（03 | 80）
异常码：02（ILLEGAL DATA ADDRESS）
```

常见异常码：

| 异常码 | 含义 | 排查建议 |
| --- | --- | --- |
| 01 | Illegal Function | 检查设备是否支持当前功能码 |
| 02 | Illegal Data Address | 检查偏移、寄存器区域、连续读取长度 |
| 03 | Illegal Data Value | 检查数量等请求数据结构是否合法 |
| 04 | Server Device Failure | 检查设备状态和内部失败原因 |

有个容易忽略的细节：异常码 **03 通常指协议请求数据字段不合法**，不应一概理解成“业务温度超限”。

## 8. 故意制造三个错误

1. **不启动模拟器**就运行 C# 客户端：观察连接拒绝；这是网络失败，不是 Modbus 异常。
2. 在代码里将 Unit ID 改成 `2`：模拟器只响应 ID 1，因此应触发超时；解释“TCP 连上了”和“设备有响应”是两回事。
3. 将读取数量从 3 改为 126：模拟器应返回 `83 03`，因为 FC03 单次最多 125 个寄存器。

完整 Python 自动化测试：

```powershell
python -m unittest discover -s examples/05-modbus-tcp-simulator -p "test_*.py" -v
```

## 9. 你要亲自完成的练习

- 练习 A：不看资料，写出读偏移 1、数量 1 的完整 12 字节请求。
- 练习 B：假设收到 `00 01 00 00 00 05 01 03 02 00 FD`，能算出温度多少摄氏度？
- 练习 C：解释为什么本例接收端读完 7 字节头之后，后续只读 `Length - 1` 而不是 `Length`。
- 练习 D：把 C# 客户端的读指令改为“偏移 2，数量 1”，解出 1200。
- 练习 E：向模拟器写偏移 0，观察 `86 02`；解释为何该寄存器不可写。
- 练习 F：提出一个无法通过 TCP 连接成功这一事实保证的工业安全问题。

<details>
<summary>点击展开参考答案</summary>

A：`00 01 00 00 00 06 01 03 00 01 00 01`（事务号示例用 1）。

B：`00 FD=253`，结合本模拟器 `0.1 ℃/单位`，即 `25.3 ℃`。

C：7 字节的 MBAP 已经包含 1 字节 Unit ID，Length 还包含 PDU，所以剩余为 `Length - 1`。

D：发送 `03 00 02 00 01` 的 PDU，回复数据区为 `04 B0`，即 1200 rpm。

E：返回异常功能码 `86` 和异常码 `02`，因为本模拟器只允许写偏移 2。

F：TCP 成功不代表身份验证、设备工作状态或现场安全联锁允许控制，也不代表指令已实际执行。
