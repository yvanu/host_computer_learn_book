# 04-6 · Modbus 工业通信自测（12 题）

> 这些题针对你已有的后端知识设计。不要背标准名词，重点是看到报文以后能知道怎么处理。建议先做 [Modbus TCP 实验](/04-modbus/tcp-lab) 和 [CRC16 实验](/04-modbus/crc-lab)，再从第一题开始。

## 基础理解（1–4）

**1.** 对一个常见标准 Modbus TCP 设备，TCP 默认端口通常是 502。本书为何使用 **1502**？

**2.** `00 01 00 00 00 06 01 03 00 00 00 03` 中，`00 06` 的含义是什么？从哪里数长度？

**3.** 设备文档写 `40001=温度`，能否直接往协议起始地址里填 `40001`？

**4.** FC03 和 FC04 都能读取“寄存器”，它们读取的数据区有何不同？

## 协议与数据（5–8）

**5.** 读 3 个保持寄存器，标准 FC03 正常响应中的 Byte Count 应是多少？

**6.** 读取结果原始值为 `0x00FD`，表中写 `0.1 ℃/单位`，实际读数为多少？为什么需要厂商寄存器表？

**7.** 同一次 `NetworkStream.ReadAsync` 得到 7 字节，就一定是完整 Modbus TCP 报文吗？

**8.** 已经读完 MBAP 的 7 个字节，`Length=9` 时还要再读多少字节 PDU？

## 错误处理和安全（9–12）

**9.** 收到 `83 02`，应先查 TCP 连接还是查请求地址和寄存器数量？

**10.** 模拟器仅允许对偏移 2 写入 0～3000 的 RPM。发送 FC06、地址 2、数值 3001，预期异常响应是什么？

**11.** 标准 Modbus TCP 需要像 RTU 一样在帧尾加 CRC16 吗？RTU 中计算得到 CRC `0xCDC5` 要如何写入报文？

**12.** 对真实电机“转一圈”命令超时，为什么不能直接无限重试？

## 答案与原因

::: details 点我展开全部答案

1. 1502 是非特权端口，减少权限和端口占用问题；**这只是本地教学模拟器**。
2. MBAP Length 表示后续 **Unit ID + PDU** 的字节数，即 6 字节。
3. 不一定。40001 常是参考编号；真实协议偏移可能为 0，但**必须查设备手册**。
4. FC03 读 Holding Register；FC04 读 Input Register。
5. 6 字节，每个寄存器 2 字节。
6. `0x00FD=253`，对应 25.3 ℃。不同厂商可能用另一种数据类型或缩放，不能固定除以 10。
7. 不一定。网络 I/O 是字节流；7 字节只是头部长度，接下来仍需按照 Length 字段读 PDU。
8. 8 字节，原因是已读 MBAP 头包含 Unit ID 1 字节。
9. 优先检查**起始偏移、数量、寄存器区**；`83 02` 已经是有效协议异常答复。
10. `86 03`。功能码 `06 | 80 = 86`，异常码 03（非法数据值）。
11. 不用。标准 Modbus TCP 使用 MBAP 封装，不添加 RTU CRC；RTU 应按低字节在前发送 `C5 CD`。
12. 命令可能已经执行但确认应答丢失；非幂等命令重复执行可能造成危险动作。应查询状态，遵循安全规程和厂商提供的确认机制。

:::

## 小挑战：手工算一帧

写出**读取偏移 1、数量 2、Unit ID 1、Transaction ID 7** 的 Modbus TCP 请求（HEX），然后对照：

::: details 参考请求

`00 07 00 00 00 06 01 03 00 01 00 02`

拆分：TID = 7，PID = 0，Length = 6，Unit = 1，FC = 03，起始地址 = 1，数量 = 2。

:::
