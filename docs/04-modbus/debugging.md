# 04-5 · 联调排障：连上了却读不到？

## 一条排障路线

```text
无法连接 TCP → 核对 IP/端口/监听/网络
       ↓ TCP 已建立
连接成功但收不到应答 → 核对 Unit ID、功能码、超时、设备占用
       ↓ 有字节返回
响应校验不通过 → 核对 MBAP 长度、TID、Protocol ID、分帧
       ↓ 协议响应合法
出现 83 02 / 83 03 → 核对地址偏移、数量、寄存器区域
       ↓ 有寄存器值
值不合理 → 核对 signed/unsigned、字序、缩放倍数、单位
       ↓ 业务数据正确
UI 不刷新 → 查看 ViewModel PropertyChanged、线程、取消逻辑
```

## 5 个最容易踩的坑

### 1. TCP 连接成功，但是一读就超时

建立 TCP 连接仅说明网络层可达，不代表设备会响应。检查 **Unit ID** 是否匹配，功能码是否支持，设备是否要求初始化，以及是否实际上跑的是 RTU over TCP 而不是标准 Modbus TCP。

### 2. 有数据，但你把它当完整报文

`ReadAsync` 并不承诺每次读到一条消息。先读 7 字节 MBAP，验证协议号与长度，再按 `Length-1` 读完整 PDU。错误长度应该拒绝，而不是无上限申请内存。

### 3. 温度显示 253 ℃，实际是 25.3 ℃

查看设备手册的缩放倍数。本书模拟器是**原始值 / 10**；真实设备可能是有符号整数、定点、32 位 float 或两寄存器自定义字序。

### 4. 读地址 40001 返回“非法地址”

将显示编号和报文偏移混为一谈了。先核对文档采用 0 基还是 1 基地址，**不要所有设备一律减 40001**。

### 5. 重试后电机动作两次

控制指令不一定幂等。网络超时可能意味着设备已执行但确认丢失。**不能对动作命令一概自动重试**；需要设备状态读回、序号或安全互锁支持。

## 推荐日志记录格式

```text
timestamp
device_id
host:port / serial
transaction_id
unit_id
function
start_offset + count
tx_hex / rx_hex
parse_result
duration_ms
error_category
```

正式业务日志中不应暴露未经授权的现场网络地址、令牌或敏感设备参数。

## 两项自测

**问题 A：** 已发 FC03，收到 `83 02`，为什么不应该立刻重连 10 次？

**答：** 这说明设备明确返回“地址/数量组合无效”，更换网络连接不会修复错误偏移。

**问题 B：** 一次 Read 返回了 7 字节，是否表示所有 MBAP 头都恰好一次读完？

**答：** 不是。它可能分多次读取；必须循环或调用 `ReadExactlyAsync`。

## 验收

给你一段失败日志，你能先判断它属于**网络、协议、数据编码、业务或 UI 层**，再决定下一步测试，不盲目修改所有层。
