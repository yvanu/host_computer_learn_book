# 03-3 · 串口、RS-232 与 RS-485

## 串口通信与 TCP 有何不同？

TCP 基于 IP 和端口，例如 `127.0.0.1:9000`。串口通常以 `COM3` 之类的设备名识别，通过串行线路传输字节。工业现场常见 RS-485 物理层上的 Modbus RTU。

串口常用参数写成 `9600 8N1`：

| 项目 | 示例 | 含义 |
| --- | --- | --- |
| 波特率 | 9600 | 每秒符号率，双方必须匹配 |
| 数据位 | 8 | 单次传输的数据位数 |
| 校验位 | N | None，无奇偶校验 |
| 停止位 | 1 | 一位停止位 |
| 端口 | COM3 | Windows 上的设备路径 |

RS-232/485 是电气接口层，不等于 Modbus 协议；**RS-485 不自动解决设备寻址、数据格式或校验问题**。

## C# 串口打开示意

需要在项目中安装 `System.IO.Ports` 包（如当前 SDK 不包含该程序集）。这只是演示打开/关闭，串口接收需要在后续章节补充分帧、线程和异常处理：

```csharp
using System.IO.Ports;

using var port = new SerialPort("COM3", 9600, Parity.None, 8, StopBits.One)
{
    ReadTimeout = 1000,
    WriteTimeout = 1000
};
port.Open();
port.Write(new byte[] { 0x01, 0x03, 0x00, 0x00 }, 0, 4);
```

⚠️ 上面的 4 字节**不是完整 Modbus RTU 请求**（没有数量和 CRC），不能把它直接作为工业设备的合法查询帧。实际操作必须严格遵循完整协议与设备文档。

## RS-485 的工程常识

RS-485 常用于多节点半双工总线，存在设备地址、终端电阻、偏置和接地等现场问题。现场要先查接线、方向、共地与总线配置，不能看到“读不到数据”就盲目重发写寄存器。

## 练习与验收

只在模拟器/虚拟串口练习：查看系统串口列表、设置波特率、观察 HEX 接收；解释为什么串口协议仍然需要定义**报文边界和超时**。

**验收：** 能区分串口、RS-485 物理层和 Modbus RTU 应用层，知道 8N1 每个字段的含义。
