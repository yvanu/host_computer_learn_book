# 04-2 · 寄存器地址和数据换算

## 先弄明白两个“地址”

设备文档可能写 `40001`、`40002`。这类以 4 开头的**参考编号**常用于人类阅读，并不意味着协议里的起始地址要写 `40001`。很多文档中 `40001` 对应报文起始偏移 `0`，但也有设备文档使用从 0 或从 1 开始的不同约定。

**按设备手册核实“显示地址/协议偏移/数据类型”。** 不能凭经验统一减 40001。

## 一个有缩放因子的例子

设备文档：

| 项 | 模拟规格 |
| --- | --- |
| 寄存器偏移 | 0 |
| 数据类型 | unsigned 16-bit |
| 单位 | 0.1 ℃ |
| 当前原始值 | 253（十六进制 `00 FD`） |

业务值为 `253 / 10 = 25.3 ℃`。但如果原始寄存器定义为有符号、BCD 或厂商自定义格式，算法就不同。

## 两个寄存器组合成 32 位值

`float32` 占两个 16 位寄存器。除了寄存器内的字节序，还可能存在 **高字在前 / 低字在前** 的词序约定；先用已知测试值核实设备实际输出，再编写解码逻辑。

## 工业安全提醒

设置类寄存器可能影响阀门、电机、压力或温控状态。首次联调先做**只读**；写寄存器需确认权限、量程、设备状态、执行结果和现场安全措施。TCP 连通不是允许执行控制的授权。

## 小测验

1. `0x012C` 换算十进制是多少？答：300。
2. 原始值 300、单位 0.1 kPa，真实值是多少？答：30.0 kPa。
3. `40001` 一定对应协议偏移 0 吗？答：不一定，依赖厂商的地址约定。
4. Modbus 读到 2 个寄存器一定表示 `float32` 吗？答：不一定，也可能是两个独立 ushort、一个 int32 等。

**验收：** 能拿到一张真实设备寄存器表后，提出需要确认的数据类型、字节顺序、缩放系数、地址偏移及异常码问题。
